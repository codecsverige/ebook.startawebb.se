# Ebook Studio — ebook.startawebb.se

تطبيق مستقل لإنشاء كتب قصيرة وأدلة عملية وكراسات تمارين، بالعربية والإنجليزية والسويدية. مبني بـ Next.js وTypeScript. لا يغيّر كود StartaWebb أو BokaNära أو MashrooHub.

## الموجود في الكود

- صفحات عامة بثلاث لغات، أمثلة تحريرية مقروءة، روابط لغات، canonical، sitemap وrobots.
- دخول برابط آمن إلى البريد باستخدام Supabase وPKCE.
- مكتبة كتب خاصة، وصف للقارئ والفكرة والأسلوب، وفهرس قابل للتعديل قبل الكتابة.
- توليد كل فصل في خطوة مستقلة باستخدام AI SDK وVercel Workflow. حفظ فوري للفصل المكتمل واستئناف الناقص.
- تحرير النص، سجل آخر 20 نسخة، تنبيه عند مغادرة نص غير محفوظ، وكشف تعارض التعديل بين نافذتين.
- ثلاثة أغلفة كتابية، وصور غلاف اختيارية بالذكاء الاصطناعي. نص الغلاف يُضاف برمجيًا لدعم العربية.
- تنزيل PDF حقيقي بخط عربي مضمّن، وتنزيل Word قابل للتعديل. الكتب خاصة ولا تُنشر في صفحات الفهرسة.
- رصيد شراء مرة واحدة عبر Lemon Squeezy: كتاب بـ 9 يورو وثلاثة بـ 19 يورو. لا اشتراكات.
- التحقق من توقيع الدفع ومعرّف المتجر والباقة وبيئة الاختبار. الدفع المكرّر لا يضيف رصيدًا مرتين. ردّ المال الكامل يعكس الرصيد مرة واحدة.
- عزل ملكية السجلات باستخدام RLS، أسرار على الخادم، تحديد الطلبات وحجز كل اتصال بالذكاء الاصطناعي قبل إرساله.

الكود قابل للبناء دون مفاتيح. تظهر رسالة إعداد واضحة عند غياب الخدمات. لا توجد استجابات AI وهمية أو دفع شكلي ناجح.

## التشغيل

يتطلب Node.js 22 أو 24. النسخ مثبتة في package-lock.json.

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
```

افتح `/en` أو `/ar` أو `/sv`. انسخ متغيرات `.env.example` إلى `.env.local` على جهازك، أو أضفها مباشرة إلى إعدادات مشروع Vercel. لا تضع الأسرار في الريبو أو المحادثة.

## 1. قاعدة بيانات وحسابات مستقلة

أنشئ **مشروع Supabase جديدًا** في منطقة أوروبية. نفّذ ملف `supabase/migrations/001_studio.sql` مرة واحدة في SQL Editor. الملف ينشئ الجداول والصلاحيات والدوال ووعاء الصور الخاص `covers`.

أضف في Vercel:

| المتغير | من أين؟ |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | عنوان المشروع الجديد |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | المفتاح العام للمشروع |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح الخدمة السري؛ خادم فقط |
| `APP_URL` | العنوان الحقيقي للمنتج، دون مسار |

في Supabase Authentication → URL Configuration، ضع Site URL الصحيح وأضف `https://YOUR-HOST/auth/callback` إلى Redirect URLs. أضف نسخة localhost للتطوير فقط. أبقِ قالب Magic Link الرسمي الذي يستخدم `ConfirmationURL` حتى تكتمل جلسة PKCE. افتح رابط الدخول في المتصفّح نفسه.

إرسال البريد الفعلي يحتاج إعداد SMTP مناسب في Supabase؛ الإرسال الافتراضي محدود ولا يصلح لإطلاق عام. فعّل حماية التسجيل وضبط حدود البريد من لوحة Supabase قبل فتح الإعلانات المدفوعة.

## 2. الذكاء الاصطناعي

أضف `AI_GATEWAY_MODEL` بقيمة نموذج لغوي حالي يدعم structured output. على Vercel تُستخدم هوية OIDC للمشروع دون مفتاح مزوّد في الواجهة. للتطوير المحلي استخدم `AI_GATEWAY_API_KEY` داخل `.env.local`.

تحقّق من قائمة النماذج الحالية عند اختيار القيمة:

```sh
curl -fsSL https://ai-gateway.vercel.sh/v1/models
```

لصور الغلاف، أضف `AI_GATEWAY_IMAGE_MODEL` لنموذج لغوي يدعم إخراج الصور عبر `generateText`. يمكن تركه فارغًا؛ تبقى الأغلفة الكتابية عاملة. الصور لا تحتاج نصًا مولّدًا داخلها.

فعّل رصيد AI Gateway وحدّ الإنفاق من لوحة حسابك. التطبيق يحدّد أيضًا: 500 محاولة اتصال للموقع يوميًا، 100 للحساب يوميًا، 8 للمعاينة المجانية و80 للكتاب المفتوح. الحدود تحسب المحاولات الفاشلة لمنع تسريب التكلفة عبر إعادة المحاولة. تحتفظ `ai_usage` بعدد الرموز؛ سجل تكلفة المزوّد في لوحة Gateway هو المرجع الفعلي للفواتير.

## 3. الدفع — بعد تجربة التوليد

أنشئ متجر Lemon Squeezy مستقلًا/مخصصًا لهذا المنتج، بعملة EUR، وباقتين **one-time / standard**: 900 سنت لكتاب واحد و1900 سنت لثلاثة. يرفض الكود إنشاء الدفع إذا كانت العملة أو الأسعار أو نوع المنتج مختلفة. لا تفعّل كمية قابلة للتغيير في صفحة الدفع.

أضف `LEMON_SQUEEZY_API_KEY` و`LEMON_SQUEEZY_STORE_ID` ومعرّفَي الباقتين `LEMON_SQUEEZY_VARIANT_ONE` و`LEMON_SQUEEZY_VARIANT_THREE`. أضف `OPERATOR_NAME` و`SUPPORT_EMAIL` الحقيقيين لصفحات الشروط والخصوصية.

أنشئ webhook إلى:

```text
https://YOUR-HOST/api/webhooks/lemonsqueezy
```

اشترك في `order_created` و`order_refunded`، واختر سر توقيع وضعه في `LEMON_SQUEEZY_WEBHOOK_SECRET`. ابدأ بـ `LEMON_SQUEEZY_TEST_MODE=true` مع مفاتيح وباقات من البيئة نفسها. لا تُخلط بيانات الاختبار مع الإنتاج؛ استخدم مشروع Supabase منفصلًا للاختبار أو احذف حساب الاختبار قبل الإطلاق.

نجاح العودة من الدفع لا يمنح الرصيد؛ webhook الموقّع فقط يفعل ذلك. اختبر التسليم وتكرار webhook وردّ المال، ثم حوّل المتجر إلى live واضبط المتغير إلى `false`. ردّ المال الجزئي يُترك للتسوية اليدوية، بينما الرد الكامل يعكس الباقة كلها. إذا استُخدم الرصيد قبل الرد، قد يصبح الحساب سالبًا. سجلات الطلبات لا تُحذف مع حذف الحساب لكنها تفقد ارتباطها الشخصي به.

## النشر والدومان

استورد **هذا الريبو فقط** كمشروع Next.js جديد على Vercel، مع Node 24. يمكن تجربة الصفحة العامة على رابط Vercel قبل شراء أي دومان. لا تشارك مفاتيح أو قاعدة بيانات موقع آخر معه.

عند ربط `ebook.startawebb.se`، أضف **سجل DNS خاصًا بـ ebook فقط** بالقيمة التي يعرضها Vercel، وعدّل `APP_URL` وRedirect URLs وأعد النشر. لا تغيّر `@` أو `www` أو Nameservers الخاصة بموقع StartaWebb. لا يحتاج المنتج إلى مشروع Sites أو استضافة إضافية مختلفة.

## ما اختُبر وما يحتاج تجربة حيّة

`npm test` يشغّل PostgreSQL حقيقيًا داخل PGlite لاختبار ملف SQL نفسه، وعزل المستخدمين، ومنع منح الرصيد من المتصفّح، والخصم مرة واحدة، وتكرار الطلبات، وفشل التوليد واستئنافه دون خصم جديد، وتعارض الحفظ، وردّ المال المكرّر أو السابق لإشعار الدفع. توجد اختبارات لحدود الإدخال وتوقيع الدفع ومنع HTML داخل التصدير.

فحص تصدير Linux الإضافي:

```sh
node --import tsx scripts/verify-export.ts
```

يتطلب `tar`, `unzip`, `pdftotext`, `pdftoppm`، وينشئ ملفات QA مؤقتة. في نظام QA الذي يمنع chown داخل tar، يمكن استخدام `EBOOK_QA_UNPACK=1` لهذا الاختبار فقط.

قبل استقبال أول زبون مدفوع: جرّب بريد دخول حقيقي، فهرسًا وفصلًا من النموذج المختار، ثم أكمل كتابًا وصدّره، وجرّب شراءً اختباريًا وردّ ماله. هذه الخطوات تحتاج مفاتيح وحسابات فعلية، ولا تعوّضها اختبارات الكود. راجع بيانات المشغّل والشروط واتفاقيات معالجة البيانات للمزوّدين قبل الإطلاق.

لا تشمل هذه النسخة الروايات أو EPUB أو النشر الآلي على Amazon أو الفرق. هذه ميزات مؤجّلة عمدًا؛ المسار الحالي هو كتاب قصير قابل للتحرير والتصدير.
