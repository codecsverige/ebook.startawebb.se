# Ebook Studio — ebook.startawebb.se

خدمة مستقلة لإنشاء كتب قصيرة وأدلة وكراسات تمارين، بالعربية والإنجليزية والسويدية. الاستضافة في مشروع Vercel الخاص بهذا الريبو. **قاعدة البيانات أصبحت Firebase**، ولا تحتاج إلى Supabase.

## المشروع الموجود الذي نستخدمه

المشروع المختار: **HyrNära — `hyrnara`**. إعداد Web App العام مأخوذ من مشروع HyrNära المنشور، ويمكن استعماله دون إنشاء قاعدة بيانات جديدة. أسماء متغيرات Ebook مستقلة، لذلك لا تؤثر متغيرات Firebase القديمة الموجودة في Vercel.

| المورد        | فصل خدمة الكتب                                                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Firestore     | كل السجلات تحت `ebookStudio/ebook-v1/`؛ منها `profiles`, `books`, `jobs`, `orders`, `aiUsage`, `rates`                                 |
| صور الغلاف    | `ebookStudio/ebook-v1/covers/<hashed-uid>/<book-id>/` داخل وعاء Storage الموجود                                                        |
| الدخول        | حساب Firebase نفسه، مع cookie خاص باسم `__Host-ebook_session` لهذا الموقع فقط                                                          |
| الرصيد والدفع | محفوظان تحت مسار الكتب؛ لا تُقرأ بيانات أو اشتراكات HyrNära                                                                            |
| حذف الحساب    | يحذف ملف الاستوديو وكتبه وصوره، ويفصل هوية المستخدم عن سجلات الطلبات؛ **لا يحذف Firebase Auth user ولا يسحب جلساته في المواقع الأخرى** |

هذا فصل منطقي للبيانات، وليس عزلًا كاملًا بين التطبيقات: Firebase Authentication والحصص والفوترة مشتركة. مفاتيح Admin تستطيع تجاوز Security Rules؛ تُحفظ على الخادم فقط. لا يوجد في هذا الريبو نشر تلقائي لقواعد Firebase أو Functions أو Hosting الخاصة بـHyrNära.

تنبيه: كود HyrNära الحالي يحذف مستخدم Firebase Authentication عند حذف حساب التطبيق. إذا استُخدمت الهوية نفسها في Ebook Studio فسيؤدي ذلك إلى إنهاء هويته المشتركة. يجب تعديل تدفق حذف HyrNära قبل إعادة نشره للمستخدمين، أو فصل Auth مستقبلًا.

## أول إعداد حي مطلوب

1. افتح [مشروع Firebase الموجود](https://console.firebase.google.com/project/hyrnara/overview). لا تنشئ مشروعًا أو قاعدة جديدة.
2. في Authentication → Settings → Authorized domains أضف `ebookstartawebbse.vercel.app`. أضف `ebook.startawebb.se` عند ربط الدومين. **أبقِ الدومينات والمزوّدين الموجودين كما هم.** Google sign-in يحتاج تفعيل Google؛ رابط البريد يحتاج تفعيل Email link فقط إذا أردت استعماله.
3. في إعدادات مشروع **Ebook الجديد وحده** في Vercel أضف سرًا واحدًا:

| المتغير                               | القيمة                                                     |
| ------------------------------------- | ---------------------------------------------------------- |
| `EBOOK_FIREBASE_SERVICE_ACCOUNT_JSON` | محتوى ملف Service Account JSON كاملًا، كنوع Secret         |
| `APP_URL`                             | `https://ebookstartawebbse.vercel.app` مؤقتًا، كنوع Config |

الاعتماد المستعمل تاريخيًا موجود باسم `FIREBASE_SERVICE_ACCOUNT_HYRNARA` داخل GitHub Environment المسمى `play-release` في ريبو `codecsverige/hyra`. GitHub لا يسمح بإظهار قيمة Secret بعد حفظها. إذا لم يعد الملف الأصلي موجودًا، أنشئ مفتاحًا إضافيًا من Service Accounts داخل **المشروع نفسه** والصق ملف JSON في المتغير أعلاه؛ هذا لا ينشئ قاعدة أو مشروعًا جديدًا ولا يحذف المفتاح القديم. لا تنشر الملف في الريبو أو المحادثة.

قيم Firebase العامة جاهزة في `src/lib/firebase-config.ts`. `.env.example` يعرض متغيرات التخصيص عند الحاجة. المفتاح العام Web API key لا يمنح حق قراءة الكتب. المتصفح يستعمل Firebase Auth فقط، وكل عمليات الكتب تمر عبر مسارات خادم تتحقق من المستخدم والملكية.

4. تحقّق من **القواعد المنشورة فعليًا** في Firebase Console قبل استقبال المستخدمين. قواعد HyrNära الموجودة في الريبو تنتهي برفض المسارات غير المعروفة في Firestore وStorage؛ لذلك مسار `ebookStudio` خاص ويكتب فيه Admin SDK من الخادم. **لا تنشر `firebase/emulator.firestore.rules` على المشروع المشترك**؛ ذلك الملف مخصص للاختبارات فقط.
5. أعد نشر مشروع Ebook وجرب دخول Google وإنشاء فكرة وحفظها، ثم مستخدمًا ثانيًا للتأكد من منع الوصول إلى كتب غيره.

رابط البريد يستعمل إرسال Firebase؛ لا توجد حاجة لإعداد Supabase أو SMTP خاص به. تبقى حدود إرسال Firebase وإعدادات المزوّد سارية. الدخول ينتج cookie آمنًا HttpOnly على الخادم لمدة خمسة أيام؛ لا تُخزَّن جلسة Firebase في localStorage. البريد الموقت لإكمال رابط الدخول فقط يُحفظ محليًا ويمكن إدخاله يدويًا على جهاز آخر.

## ما يقدمه الموقع

- صفحات عامة وأمثلة تحريرية بثلاث لغات، RTL للعربية، canonical وhreflang وsitemap.
- وصف الفكرة والقارئ والأسلوب، ثم فهرس قابل للتعديل، ثم فصل مجاني واحد.
- توليد الفصول في خطوات دائمة باستخدام AI SDK وVercel Workflow؛ حفظ كل فصل واستئناف الناقص.
- تحرير وحماية تعارض التعديل، آخر 20 نسخة، وتنبيه عند مغادرة تعديلات غير محفوظة.
- ثلاثة أغلفة كتابية وصور غلاف اختيارية؛ الصور خاصة وتُعرض عبر مسار يتحقق من صاحب الكتاب.
- PDF حقيقي بخط عربي مضمّن وWord قابل للتعديل.
- رصيد شراء مرة واحدة عبر Lemon Squeezy: €9 لكتاب و€19 لثلاثة. لا اشتراك.
- معاملات Firestore ذرية لحجز الرصيد والمهام، ومنع تكرار الطلبات وإشعارات الدفع ورد المال.

الحماية المالية والمهام لا تعتمد على كتابة المتصفح إلى Firestore. تحفظ محاولات AI قبل الاتصال بالمزوّد حتى تحتسب المحاولات الفاشلة. المعاينة 8 محاولات، الكتاب المفتوح 80، الحساب 100 محاولة في 24 ساعة والموقع 500 يوميًا. يوجد حد 30 مشروعًا للحساب، و30 مهمة في 24 ساعة، و50 مهمة لكل كتاب، و20 نسخة محفوظة. الحد يومي للموقع بحسب UTC. أعدّ ميزانية وتنبيهات في Google Cloud وAI Gateway؛ عدّادات التطبيق ليست حد إنفاق من المزوّد.

الكتب تُرفض قبل تجاوز حجم آمن لمستند Firestore، دون اقتطاع النصوص. سجل النسخ يحمل عناوين فقط حتى تُطلب نسخة واحدة، وقائمة الكتب لا تنقل مخطوطات الكتب كلها إلى المتصفح.

## تفعيل الذكاء الاصطناعي

أضف `AI_GATEWAY_MODEL` لنموذج حالي يدعم structured output. على Vercel يستعمل AI Gateway هوية OIDC؛ محليًا أضف `AI_GATEWAY_API_KEY` في `.env.local`. اختَر نموذجًا من [القائمة الحالية](https://ai-gateway.vercel.sh/v1/models)، واضبط الرصيد والميزانية في لوحة Gateway.

صور الغلاف اختيارية: `AI_GATEWAY_IMAGE_MODEL` لنموذج يدعم إخراج الصور عبر `generateText`. عند تركه فارغًا تعمل الأغلفة الكتابية. تكلفة الرموز والصور منفصلة عن استضافة الموقع. لا تُستدعى النماذج أثناء اختبارات الكود.

## الدفع — بعد نجاح التوليد والتصدير

أعدّ متجر Lemon Squeezy بعملة EUR وباقتين one-time / standard بسعر 900 و1900 سنت. أضف:

- `LEMON_SQUEEZY_API_KEY`, `LEMON_SQUEEZY_STORE_ID`
- `LEMON_SQUEEZY_VARIANT_ONE`, `LEMON_SQUEEZY_VARIANT_THREE`
- `LEMON_SQUEEZY_WEBHOOK_SECRET`, `LEMON_SQUEEZY_TEST_MODE=true` أولًا
- `OPERATOR_NAME`, `SUPPORT_EMAIL` الحقيقيين

Webhook: `https://YOUR-HOST/api/webhooks/lemonsqueezy` مع `order_created` و`order_refunded`. يرفض التطبيق أسعارًا أو عملة أو نوع دفع مختلفًا. webhook الموقّع فقط يضيف الرصيد؛ العودة من الدفع لا تفعل ذلك. جرّب تكرار الإشعار ورد المال؛ الرد الكامل يعكس الباقة مرة واحدة، والرد الجزئي للتسوية اليدوية. قد يصبح الرصيد سالبًا إذا رُدّ المال بعد استخدامه. لا تُخلط مفاتيح ومتغيرات الاختبار مع live؛ نظّف بيانات حساب الاختبار أو اعزل بيئته قبل الإطلاق.

## التشغيل والاختبارات

Node.js 22 أو 24:

```sh
npm ci
npm test
npm run typecheck
npm run build
npm run dev
```

اختبار Firestore وAuthentication الحقيقيين بالمحاكي يحتاج **Java 21+**:

```sh
npm run test:firebase
```

يستخدم المشروع الوهمي `demo-ebook-studio` ومنافذ localhost فقط، ولا يتصل بقاعدة حية. يغطي معاملات الخصم المتزامن، تكرار الدفع ورد المال، حدود المعاينة واستكمالها برصيد، الحفظ والنسخ، قفل الحذف أثناء التوليد، بقاء بيانات الموقع الآخر، والتحقق من جلسات Auth. يمكن تعيين `EBOOK_SHARED_RULES_PATH` لمسار نسخة قواعد HyrNära لفحص منع الوصول إلى مسارات الكتب مع استمرار وصول مستخدم HyrNära إلى ملفه؛ لا ينشر الاختبار تلك القواعد.

فحص PDF/Word على Linux عند تعديل التصدير:

```sh
node --import tsx scripts/verify-export.ts
```

يتطلب `tar`, `unzip`, `pdftotext`, `pdftoppm`. خيار `EBOOK_QA_UNPACK=1` خاص بنظام QA الذي يمنع chown.

## النشر والدومان

هذا الريبو يبقى في **مشروع Vercel مستقل**. الدومين المختار **`ebook.startawebb.se`**؛ لا تشتري دومينًا. أضفه للمشروع الجديد، ثم في Cloudflare أضف CNAME باسم `ebook` بالقيمة التي يعرضها Vercel لهذا المشروع. لا تعدّل `@` أو `www` أو MX أو Nameservers الخاصة بـStartaWebb.

بعد التأكد من الدومين، غيّر `APP_URL` وأضفه إلى Firebase Authorized domains وأعد النشر. قاعدة البيانات ومسارها لا يتغيران بسبب تغيير الدومين. الانتقال لاحقًا إلى مشروع Firebase مستقل يحتاج ترحيل بيانات وهوية المستخدمين والصور؛ ليس تغيير مفاتيح فقط.

راجع شروط خطة Vercel المناسبة للعمل التجاري وتسعير Firebase وAI قبل تفعيل البيع؛ لا توجد ترقية مدفوعة آلية. غياب الإعدادات يعرض إشعار تفعيل واضحًا، ولا يُرجع توليدًا أو دفعًا وهميًا.

## الحماية من الانقطاع وتكاليف الذكاء الاصطناعي (أكتوبر 2026)

لا تُغيَّر النماذج أو المزوّدات الحالية تلقائيًا، ولا يتم تفعيل الدفع حتى يقرر المشغّل ذلك صراحة. يُحفظ كل فصل في Firestore بعد اكتماله، ويمكن متابعة الأجزاء الناقصة بعد فشل توليد الكتاب. تُستخدَم هوية طلب ثابتة داخل تبويب المتصفح لتجنّب إنشاء مهمتين مدفوعتين عند ضياع استجابة الشبكة. تُحفظ المسودات غير المرسلة محليًا وتُمنع استجابات الحفظ القديمة من استبدال أحدث تعديل.

تحد المكتبة من إعادة إرسال طلب AI مرة واحدة تلقائيًا؛ لا تعيد Workflow SDK تنفيذ خطوات AI نفسها بلا حدود فوق إعادة المحاولة في SDK. تتم حجزات الاستخدام بصورة ذرية **قبل** استدعاء AI، وتشمل الطلبات التي قد تفشل عند المزوّد؛ هذا احتراز لمنع التكلفة المفتوحة.

حدود التشغيل الافتراضية في التطبيق: 80 طلب AI لكل الموقع يوميًا، 32 لكل مستخدم خلال 24 ساعة، 40 لكل كتاب طوال عمره (أو 8 قبل فتحه)، 8 محاولات صور يوميًا للموقع و3 للمستخدم. يمكن تخفيضها فقط بمتغيرات `EBOOK_AI_GLOBAL_DAILY_LIMIT` و`EBOOK_AI_USER_DAILY_LIMIT` و`EBOOK_AI_BOOK_LIFETIME_LIMIT` و`EBOOK_AI_IMAGE_GLOBAL_DAILY_LIMIT` و`EBOOK_AI_IMAGE_USER_DAILY_LIMIT`. تُفحص الحدود قبل إجراء استدعاء مدفوع وتعمل على الصور أيضًا. **هذه حدود للطلبات وليست ضمانًا لسقف نقدي**؛ يجب إعداد سقف مالي وتنبيهات إنفاق في لوحة Vercel AI Gateway، ومراقبة التكلفة الفعلية للرموز والصور.

لم يُضف هذا التحديث أي نموذج جديد أو OpenAI API مباشر، ويبقى تسجيل دخول ChatGPT غير مفعل حتى صدور بيانات الموافقة.

## التحقق قبل البيع

اختبارات الكود والمُحاكي لا تثبت تشغيل الخدمات الحية. يلزم اختبار دخول من Google وبريد حقيقي، توليد فهرس وفصل وكتاب كامل، تنزيله باللغات الثلاث، وشراء اختباري وتسليم webhook ورد مال، والتحقق من قواعد Firebase المنشورة. راجع بيانات المشغّل والخصوصية قبل فتح الدفع. لا تشمل النسخة الروايات أو EPUB أو النشر الآلي على Amazon أو الفرق.
